# MAMO BOAT PRESS PILOT v4.0.1

実際のBOAT RACEに、換金・購入・譲渡できないBメダルだけで参加する行動記録Webアプリです。サービス名は「MAMO BOAT」、仮想投票機能名は「AIR BET」です。現金舟券の代わりに使い、仮想投票へ置き換えた予定額、現金で買いたい気持ち、予定額の変化、短時間連投などを記録します。

BOAT RACE公式のサービスではありません。公式ロゴ・公式画面・現金投票・入出金機能は使用しません。v4.0.0では常駐の公式投票ボタン、DOUBLE WIN、防衛スタンプ、的中連動の特典表示を表側から外しました。v4.0.1では、本人が同意した匿名イベントだけをSupabaseへ中央集約できるようにしました。

## v4.0.1のMAMO BOAT編集部

AIの立ち位置を、勝敗・艇・買い目・賭け金を判断する予想AIではなく、本人の行動事実を短い記事へ編集する「行動記者」に固定しました。現在は外部生成AIへ接続せず、検証可能な端末内ルールだけで紙面を作成します。

- 加音 守（かね まもる）：MAMO BOAT編集部の競艇担当記者。利用者の選択過程を取材
- 新人記者：読者の疑問を代弁する成人のデータ記者
- 既存のメインキャラクター：守の幼馴染であるトップレーサー。予想ではなく準備と自己管理を象徴
- MAMO朝刊：前日の記録
- MAMO週間：直近7日と前の7日の比較
- MAMO月刊：直近30日と前の30日の比較
- 紙面は「事実 → 傾向 → 問い」の順で構成し、「しっくりくる／違う／今は答えない」を端末へ記録
- 記録がない期間を「賭けなかった」と推測しない
- B的中後に「現金ならよかった」と感じる強さを任意記録

### 会員設計（PILOT）

決済は未実装です。画面と質問量の検証用として、端末内で次のPILOTプランを切り替えられます。

- 無料：AIR BET、基本記録、安全介入
- 梅・月300円案：MAMO朝刊
- 竹・月500〜700円案：朝刊・週間・月刊
- 松・月1,000円案：全紙面と、本人が選ぶ深掘り取材

安全介入、基本記録、データ削除・書き出しは有料化しません。価格は未確定で、PILOT版では料金は発生しません。

## Bウォレット

航海EXPと任意のB追加は廃止済みです。初回残高は100,000Bで、自動復活しません。BはAIR BETで減り、的中時は公式確定払戻と同額のBが加算されます。返還時は対象Bだけ戻り、外れた場合は戻りません。全増減を台帳へ保存します。

## 完成しているレース体験

1. 公式公開の番組表日次LZHから、当日開催場・各場1〜12R・各レース6艇・登番・選手名・締切予定時刻を取得
2. Bファイルの場ごとの見出しから、大会名、第何日、開催開始日を取得
3. 公式グレード日程の低頻度キャッシュと開催日・場を照合し、SG、PG1、GⅠ、GⅡ、GⅢ、一般を表示
4. 開催一覧から「場 → 1〜12R → 出走表 → B投票」と進む導線
5. 単勝、複勝、2連単、2連複、拡連複、3連単、3連複を、通常・BOX・フォーメーションでB投票
6. 締切済レースを灰色表示し、発売中・締切済・結果確定と残り時間を表示
7. 選手名から公式レーサープロフィール、舟券種から対応する公式オッズ、各レースから公式結果を別画面で確認
8. 公式公開の競走成績日次LZHから、実着順と7舟券種の確定払戻を取得してBメダルを自動精算
9. 仮想投票額を「仮想投票へ置き換えた金額」として自動集計し、任意で投票前後の衝動を記録
10. 低い納得度×高い現金衝動、取り返したい参加、外れ後の追い上げ、短時間の金額増加・連投を分析
11. 確定結果を日別アーカイブへ残し、日付・場・R・選手名・大会名から検索
12. 公式結果・選手情報など、照合に必要な公式情報だけを本人操作で別画面表示
13. 通常・BOX・フォーメーション、異なる舟券種の買い目を同じ投票へ複数追加し、全点のBメダル額を一括変更
14. 締切前に取得した7舟券種の参考オッズを、更新時刻・遅延注意とともに表示し、買い目へ自動反映
15. 結果待ちの記録から最新JSONを即時再読込し、到着済みならその場でB精算
16. レース画面の場名を押して、その場で別の開催場へ切り替え
17. 加音 守の朝刊・週間・月刊を端末内ルールで発行し、本人の回答を保存
18. 無料・梅・竹・松のPILOT表示を切り替え、分析密度と質問負担を検証
19. 5〜10人程度のテスターを番号で分け、同意がある場合だけ匿名行動イベントを中央集約

## デザイン

「少年漫画の熱量 × 大人の航海管理 × スポーツ新聞」を、白・濃紺・青緑と紙面色で構成しています。トップの既存キャラクターは加音 守ではなく、守の幼馴染であるトップレーサーです。MAMO編集部には加音 守、新人記者、トップレーサーの役割を明示します。キャラクター、ロゴ、アイコン、画面構成はMAMO BOAT用のオリジナルで、公式ロゴや既存作品のキャラクターは使用しません。

画面幅744px以上では左ナビ、744px未満では下ナビを使用します。最低確認サイズはスマートフォン360×640px、PC・タブレット744×600pxで、低いウィンドウでも操作ボタンとモーダル末尾までスクロールできます。

## 負荷・権利への配慮

- 約15分ごとに、公式がダウンロード用に公開している番組表・競走成績LZHを取得します。
- グレード日程は、公式のSG・PG1、G1・G2、G3の3ページだけを週に1回、直列で取得し、JSONへキャッシュします。
- GitHub ActionsはLZHを1並列で取得し、データが変わらなければコミットしません。
- オッズは締切45分前以内の各場の次レースだけを対象に、公式5画面を直列で約15分周期に更新します。10分以内の重複実行は抑止し、並列巡回・秒単位更新は行いません。
- オッズ取得が連続3回失敗した場合はその実行の取得を打ち切り、直前値を維持します。1回の実行にも時間上限を設けています。
- アプリには「参考オッズ」「更新時刻」「リアルタイム・確定値ではない」旨を常に一緒に表示します。B精算は参考オッズではなく、公式日次成績の確定払戻を使います。
- レーサープロフィール、映像、公式の最終オッズ・個別結果は利用者が押した場合だけ公式サイトを開きます。アクセストークンをブラウザへ埋め込むプロキシは使用しません。
- 公式ロゴ、公式サイトの画像・CSS・画面レイアウトは使用しません。舟番の1〜6号艇色など、投票に必要な一般的な表示規則だけを使用します。
- 公式サイトの公開条件やサイトポリシーが変わった場合は、同期運用を見直してください。

公式公開データ案内: <https://www.boatrace.jp/owpc/pc/extra/data/download.html>

## 会場振り分けと大会情報

日次B/Kファイルは複数場を連結したファイルです。会場名を1回だけ推定せず、公式ファイル内の制御行を場境界として扱います。

- 番組表: `NNBBGN` から `NNBEND`
- 競走成績: `NNKBGN` から `NNKEND`
- `NN` は01〜24の場コード
- 「ボートレース○○」見出しは、制御行欠損時の補助判定だけに使用

生成前に、開催場ごとに12R、各Rに1〜6号艇、4桁の登番、氏名、締切時刻が揃っているかを検証します。不完全なら処理を失敗させ、既存JSONは原子的書き込みにより維持します。蒲郡（07）・常滑（08）を含む全国24場へ対応しています。

BBGN直後の実データにある「場名・第何日」と、番組表見出し下の省略されていない大会名を解析します。グレードは大会名から推測せず、公式グレード日程の開催日・場と一致した場合だけ付与します。

## データ更新と結果の遅延

`Sync BOAT RACE data` が次を生成します。

- `data/today.json`: JST当日の検証済みデータ
- `data/YYYY-MM-DD.json`: 日付をまたいだ未精算用の履歴データ
- `data/results/YYYY-MM-DD.json`: 着順・全舟券種払戻・選手名を残す検索用アーカイブ
- `data/results/index.json`: 保存済み日付の索引
- `data/grade_schedule_YYYY.json`: 公式グレード日程の週次キャッシュ

参考オッズは各レースの `odds.types` に、舟券種別の買い目、倍率、公式更新時刻、取得時刻を保存します。取得できない場合も番組表・結果の更新は失敗させず、前回の倍率があれば維持します。

通常の番組表・日次成績・参考オッズ同期はJST 06:00〜23:45に約15分ごと、前日成績の最終確認はJST 00:35と05:35に実行します。これとは別に、終了済みでまだ結果未確定のレースだけを対象に、公式の1レース結果画面を約10分周期で低頻度確認します。確認開始は締切予定時刻の5分後です。開催場が多い日でも特定場の中間レースが候補外に残らないよう、各場の古い未確定レースから均等に巡回して直列取得します。グレード日程は月曜日JST 09時台にだけ再取得します。アプリはGitHub Pages上のJSONだけを5分ごとに確認します。GitHub Actionsの混雑、公式結果の確定、GitHub Pagesの配信には追加の遅れが生じる場合があります。

結果画面で7舟券種の払戻がすべて確定したレースは、日次LZH競走成績を待たず `today.json` へ反映します。公式確定後5〜15分程度を目安としますが、GitHub ActionsやGitHub Pagesの遅延により長くなる場合があります。後から日次LZHが公開された場合は、日次成績側の確定結果を優先します。返還艇を含む買い目だけの返金、舟券種単位の不成立にも対応します。

結果待ちカードでは、「公式結果を確認中」「公式結果ページ確認済み・精算データ待ち」「公式結果の確認を再試行中」を区別して表示します。「最新データを再確認」は、ブラウザキャッシュを使わずGitHub Pages上の最新JSONを再読込します。GitHub Actionsそのものを即時実行するボタンではありません。新しい結果が到着済みならその場でB精算し、まだ未到着の場合は待機案内と公式結果へのリンクだけを表示します。

## 複数人パイロットの行動データ

設定画面で各テスターへ `P01`、`P02`、`P03`、`P04` のような重複しない番号を割り当てます。人数を3人へ固定するコード上の制限はありません。最初は5〜10人程度で記録品質と運用負荷を確認します。記録する主な指標は次のとおりです。

- B投票回数、買い目数、舟券種、B投票額
- 仮想投票額、仮想投票へ置き換えた金額、B台帳
- 投票前後の現金衝動、レース後の追い上げ衝動、本人の納得度、参加理由
- 的中・外れ・返還、B的中後の「現金ならよかった」強度
- 朝刊・週間・月刊を開いた種類と、記事への任意回答
- PILOTプラン、発行頻度、編集部／シンプル表示の選択

氏名、メールアドレス、自由記述メモ、決済情報、端末の広告IDは送信しません。イベントにはテスター番号、セッション番号、日時、画面、場コード、R番号、上記の数値・選択式項目だけを含めます。

中央集約は `mamoboat-pilot` Supabaseへ接続済みです。ただし、設定画面で本人が匿名送信へ同意するまでは送信しません。`supabase/mamoboat_pilot.sql` は次を設定します。

- 匿名クライアントは検証済みイベント受付関数の実行だけ可能
- 元テーブルの閲覧、直接追加、更新、削除は禁止
- 同じイベントIDの再送は受付関数内で安全に無視
- 管理者専用の `private.pilot_overview` と `private.pilot_participant_daily` を作成
- 1回100件、構造化payload 8KB以下に制限

接続状態と確認方法は `CENTRAL_AGGREGATION.md` を参照してください。不同意の場合もイベントは端末内に残り、設定画面からCSVまたは全記録JSONを書き出せます。

## データ保管

投票記録、実結果、仮想置換額、B台帳、新聞の発行設定と任意回答はブラウザの `localStorage` に残り、設定画面からJSONを書き出せます。旧版の特典フィールドはデータ移行のため保持しますが、v4.0.0以降の画面には表示しません。公式の確定結果は `data/results/YYYY-MM-DD.json` に日別保存し、検索対象から消しません。匿名イベントは端末内に最大5,000件を保持し、同意と集約先設定が揃った場合だけSupabaseへ送信します。送信済みの中央データは管理者が削除するまで保持されます。

初回残高は100,000Bです。任意追加・自動補充・換金は行いません。B残高はAIR BET、公式確定払戻、公式返還だけで変動します。PWAはデータJSONを常に再確認し、通信失敗時だけ直前キャッシュへフォールバックします。

## 公開前の注意

実レースを用いた仮想投票の有料提供、公式データの商用利用、行動分析の効果表示について、一般公開・決済導入前に専門家と公式側の確認が必要です。この版は、20歳以上5〜10人程度の閉鎖テストで表示の正確さ、不快感、B的中後のFOMO、新聞が現金投票を刺激しないかを確認するためのPILOTです。
