# まもボート PERSONAL v3.7.1

実際のBOAT RACEに、換金・購入・譲渡できないBメダルだけで参加する個人用Webアプリです。現金舟券の代わりに使い、現金を使わずに済んだ金額、衝動、追い上げ、短時間連投などを端末内へ記録します。

BOAT RACE公式のサービスではありません。公式ロゴ・公式画面・現金投票・入出金機能は使用しません。全画面の「公式投票へ」は、確認後に公式TELEBOATログインを別画面で開く外部リンクです。

## v3.7.1で完成している流れ

1. 公式公開の番組表日次LZHから、当日開催場・各場1〜12R・各レース6艇・登番・選手名・締切予定時刻を取得
2. Bファイルの場ごとの見出しから、大会名、第何日、開催開始日を取得
3. 公式グレード日程の低頻度キャッシュと開催日・場を照合し、SG、PG1、GⅠ、GⅡ、GⅢ、一般を表示
4. 開催一覧から「場 → 1〜12R → 出走表 → B投票」と進む導線
5. 単勝、複勝、2連単、2連複、拡連複、3連単、3連複を、通常・BOX・フォーメーションでB投票
6. 締切済レースを灰色表示し、発売中・締切済・結果確定と残り時間を表示
7. 選手名から公式レーサープロフィール、舟券種から対応する公式オッズ、各レースから公式結果を別画面で確認
8. 公式公開の競走成績日次LZHから、実着順と7舟券種の確定払戻を取得してBメダルを自動精算
9. レース後に現金購入の有無と衝動を記録し、「守った現金」を集計
10. 低自信×高衝動、取り返したい参加、外れ後の追い上げ、短時間の金額増加・連投を分析
11. 確定結果を日別アーカイブへ残し、日付・場・R・選手名・大会名から検索
12. 全画面から、現金利用の確認を挟んで公式TELEBOATログインを別画面で開く
13. 通常・BOX・フォーメーション、異なる舟券種の買い目を同じ投票へ複数追加し、全点のBメダル額を一括変更
14. 締切前に取得した7舟券種の参考オッズを、更新時刻・遅延注意とともに表示し、買い目へ自動反映
15. 結果待ちの記録から最新JSONを即時再読込し、到着済みならその場でB精算
16. レース画面の場名を押して、その場で別の開催場へ切り替え
17. 「公式投票」は操作領域へ重ねず、スマホでは右側の専用レール、PCではアプリ枠の外側に表示

## デザイン

「少年漫画の熱量 × 大人の航海管理」を、白・濃紺・青緑を中心に構成しています。トップはキャラクター、B残高、本日の開催、3列の開催場カードを一画面へまとめ、開催場を押すと1〜12Rへ進みます。終了・未開催は同じ一覧内で灰色表示します。「公式投票」は他のボタンを隠さないよう、アプリ内容とは別の右側レールに置きます。キャラクター「マモル」、ロゴ、アイコン、画面構成はまもボート用のオリジナルで、公式ロゴや既存作品のキャラクターは使用しません。

## 負荷・権利への配慮

- 約15分ごとに、公式がダウンロード用に公開している番組表・競走成績LZHを取得します。
- グレード日程は、公式のSG・PG1、G1・G2、G3の3ページだけを週に1回、直列で取得し、JSONへキャッシュします。
- GitHub ActionsはLZHを1並列で取得し、データが変わらなければコミットしません。
- オッズは締切35分前以内のレースだけを対象に、公式5画面を直列で原則1レース1回取得します。取得済み値を再利用し、並列巡回・秒単位更新は行いません。
- オッズ取得が連続3回失敗した場合はその実行の取得を打ち切り、直前値を維持します。1回の実行にも時間上限を設けています。
- アプリには「参考オッズ」「更新時刻」「リアルタイム・確定値ではない」旨を常に一緒に表示します。B精算は参考オッズではなく、公式日次成績の確定払戻を使います。
- レーサープロフィール、映像、公式の最終オッズ・個別結果は利用者が押した場合だけ公式サイトを開きます。アクセストークンをブラウザへ埋め込むプロキシは使用しません。
- 公式ロゴ、公式サイトの画像・CSS・画面レイアウトは使用しません。舟番の1〜6号艇色など、投票に必要な一般的な表示規則だけを使用します。
- 公式サイトの公開条件やサイトポリシーが変わった場合は、同期運用を見直してください。

公式公開データ案内: <https://www.boatrace.jp/owpc/pc/extra/data/download.html>

## 会場振り分けと大会情報

日次B/Kファイルは複数場を連結したファイルです。会場名を1回だけ推定せず、公式ファイル内の制御行を場境界として扱います。

- 番組表: `NNBBGN` から `NNBEND`
- 競走成績: `NNKBGN` から `NNKEND`
- `NN` は01〜24の場コード
- 「ボートレース○○」見出しは、制御行欠損時の補助判定だけに使用

生成前に、開催場ごとに12R、各Rに1〜6号艇、4桁の登番、氏名、締切時刻が揃っているかを検証します。不完全なら処理を失敗させ、既存JSONは原子的書き込みにより維持します。蒲郡（07）・常滑（08）を含む全国24場へ対応しています。

BBGN直後の実データにある「場名・第何日」と、番組表見出し下の省略されていない大会名を解析します。グレードは大会名から推測せず、公式グレード日程の開催日・場と一致した場合だけ付与します。

## データ更新と結果の遅延

`Sync BOAT RACE data` が次を生成します。

- `data/today.json`: JST当日の検証済みデータ
- `data/YYYY-MM-DD.json`: 日付をまたいだ未精算用の履歴データ
- `data/results/YYYY-MM-DD.json`: 着順・全舟券種払戻・選手名を残す検索用アーカイブ
- `data/results/index.json`: 保存済み日付の索引
- `data/grade_schedule_YYYY.json`: 公式グレード日程の週次キャッシュ

参考オッズは各レースの `odds.types` に、舟券種別の買い目、倍率、公式更新時刻、取得時刻を保存します。取得できない場合も番組表・結果の更新は失敗させず、前回の倍率があれば維持します。

通常同期はJST 06:00〜23:45に約15分ごと、前日成績の最終確認はJST 00:35と05:35に実行します。グレード日程は月曜日JST 09時台にだけ再取得します。アプリはGitHub Pages上のJSONだけを5分ごとに確認します。GitHub Actionsの混雑、公式LZHの公開、GitHub Pagesの配信には追加の遅れが生じる場合があります。

日次競走成績はレース直後ではなく、場単位または公開タイミングにより遅れて反映されます。直後の結果は「公式結果」で確認でき、B精算は日次成績が公開された後に自動で行われます。

結果待ちカードの「結果を今すぐ再確認」は、ブラウザキャッシュを使わずGitHub Pages上の最新JSONを再読込します。新しい競走成績が到着済みなら即時精算します。まだ未到着の場合はユーザー向けの待機案内と公式結果へのリンクだけを表示し、GitHubの操作画面は表示しません。

## データ保管

行動記録はブラウザの `localStorage` だけに保存され、外部サーバーへ送信しません。設定画面からJSONを書き出せます。初回残高は10,000Bです。残高欄を押した場合だけ100B・1,000B・10,000Bを手動追加でき、日替わり・週替わりの自動補充は行いません。PWAはデータJSONを常に再確認し、通信失敗時だけ直前キャッシュへフォールバックします。
