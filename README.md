# まもボート PERSONAL v2.7

実際のBOAT RACEに、換金・購入・譲渡できない仮想メダルだけで参加する個人用Webアプリです。現金舟券の代わりに使い、現金を使わずに済んだ金額、衝動、追い上げ、短時間連投などを端末内へ記録します。

## 完成している流れ

1. 公式の番組表日次LZHから、当日開催場・各場1〜12R・6艇・登番・選手名・締切予定時刻を取得
2. 通常3連単、BOX、フォーメーションを仮想メダルで記録
3. 公式の競走成績日次LZHから、実着順・3連単払戻・人気を取得
4. 的中、外れ、同着による複数払戻、3連単不成立時の返還を自動精算
5. レース後に実際の現金購入有無と衝動を記録し、「守った現金」を集計
6. 低自信×高衝動、取り返したい参加、短時間の金額増加、外れ後の追い上げ、短時間連投を分析

現金の購入・入金・出金機能はありません。仮想メダルとEXPに金銭的価値はありません。

## 会場振り分けの修正

日次B/Kファイルは複数場を連結したファイルです。会場名を1回だけ推定する方式は使わず、公式ファイル内の制御行を場境界として扱います。

- 番組表: `NNBBGN` から `NNBEND`
- 競走成績: `NNKBGN` から `NNKEND`
- `NN` は01〜24の場コード
- 「ボートレース○○」見出しは、制御行欠損時の補助判定だけに使用

生成前に、開催場ごとに12R、各Rに1〜6号艇、4桁の登番、氏名、締切時刻が揃っているかを検証します。不完全なら処理を失敗させ、既存の `data/today.json` は原子的書き込みにより維持されます。

## 公式データ同期

GitHub Actionsの `Sync BOAT RACE data` が次を生成します。

- `data/today.json`: JST当日の検証済みデータ
- `data/YYYY-MM-DD.json`: 日付をまたいだ未精算に使う履歴データ

通常同期はJST 06:15〜23:15に毎時、前日成績の最終取得はJST 00:35と05:35に実行します。実データに変化がない場合は `generatedAt` を維持するため、不要なコミットは作りません。手動実行では任意の `target_date` も指定できます。

競走成績LZHがまだ公開されていない時間帯は番組表だけを安全に更新します。公開後の同期で結果が追加され、アプリ起動時・再読込時・画面復帰時に未精算記録を自動精算します。

## 配置と初回実行

1. ZIP内のファイルをGitHub Pages用リポジトリのルートへ配置
2. リポジトリのActionsで `Sync BOAT RACE data` を手動実行
3. Pagesを開き、設定画面の同期件数を確認
4. 必要ならリポジトリ設定のWorkflow permissionsで書き込みを許可

同梱の `data/today.json` は2026-08-09公式Bファイルを変換した実データで、14場・168R・1008艇・警告0件です。架空選手のフォールバックは削除してあります。

## 補足

- オッズの常時自動取得は行いません。予想オッズは任意入力でき、精算は公式の確定払戻を使います。
- 記録はブラウザの `localStorage` に保存されます。設定画面からJSONを書き出せます。
- 週の仮想メダルは月曜に10,000Cへリセットします。前週レースの遅延払戻は記録には残りますが、今週残高には加算しません。
- PWAはアプリ本体をnetwork-first、公式JSONをno-storeで確認し、失敗時だけ直前キャッシュへフォールバックします。古い日付では仮想投票を停止します。
